# 예약매도 스크립트 (앱 없이 동작)

StockFlow 앱을 켜두지 않아도, 윈도우 작업 스케줄러가 지정한 시각에 매도 주문을 발사한다.
`SOR` 라우팅이라 **KRX + NXT 통합**으로 나가므로 NXT 프리마켓(08:00~08:50)에도 체결된다.

| | 앱 SOR 예약매도 | 이 스크립트 |
|---|---|---|
| NXT 시간대 | 가능 | 가능 |
| 앱 실행 필요 | 필요 | 불필요 |
| PC 절전 상태 | 발사 안 됨 | **깨워서 발사** |
| PC 전원 꺼짐 | 발사 안 됨 | 발사 안 됨 |

PC 전원이 꺼져 있으면 어느 쪽도 동작하지 않는다. 전원을 완전히 꺼야 한다면
앱의 `예약매도(KIS·KRX)`를 쓰되, 그건 KRX 정규장 09:00에만 나간다.

## 등록 — StockFlow 앱에서 (권장)

앱을 켜고 관심/보유종목 목록에서 종목을 **우클릭 → `윈도우 예약매도 (앱꺼도OK·절전깨움)`**.
수량·목표가·발사 시각을 넣고 확인하면 앱이 아래 스크립트를 대신 실행해 작업 스케줄러에 등록한다.
등록이 끝나면 앱을 꺼도 된다. 예약은 앱이 아니라 **윈도우가 보관**한다.

등록된 예약은 메인 화면의 **`윈도우 예약목록`** 버튼에서 확인·취소하고, 같은 창의
`로그 폴더` 버튼으로 실행 기록을 열 수 있다.

> 앱의 `SOR 예약매도 (앱·NXT포함)`과는 다른 기능이다. 그쪽은 앱이 떠 있어야 발사되고,
> 이쪽은 앱이 꺼져 있어도 발사된다. 예약목록도 서로 별개다.

## 등록 — 명령줄에서

```powershell
# 2026-08-17 08:00 에 KB금융 2주, 목표가 170,000원
.\Register-SellTask.ps1 -At '2026-08-17 08:00' -Symbol 105560 -Quantity 2 -TargetPrice 170000
```

| 인자 | 설명 |
|---|---|
| `-At` | 발사 시각 |
| `-Symbol` | 종목코드 6자리 |
| `-Quantity` | 주식 수 또는 `All`(보유 전량) |
| `-TargetPrice` | 목표가(하한). 이 가격 미만 호가에는 팔지 않음 |
| `-RetryIntervalSec` | 주문 거부 시 재시도 간격, 기본 60초 |
| `-MaxRetries` | 최대 재시도, 기본 10회 |
| `-FillCheckSec` | 주문 후 체결 확인까지 대기, 기본 3초 |
| `-ChaseMinutes` | 호가 추격 시간 상한, 기본 60분 |
| `-RecoverIntervalSec` | 통신 끊겼을 때 재접속 간격, 기본 10초 |
| `-RepeatDays` | 며칠 동안 매일 반복할지. 1이면 1회 |
| `-DryRun` | 주문을 보내지 않고 판단 결과만 로그로 남김 |

```powershell
.\Register-SellTask.ps1 -List                                   # 등록 목록
.\Register-SellTask.ps1 -Remove -TaskName 'StockFlow-Sell-105560'  # 삭제
```

## 발사 시각에 하는 일 — 호가 추격

1. 캐시된 토큰을 확인하고, 없거나 만료됐으면 새로 발급받는다.
2. **주문가능수량(`ord_psbl_qty`)** 을 조회한다. `All`이면 그만큼 전량, 숫자면 그 값을
   넘지 않게 자른다. 보유수량이 아니라 주문가능수량인 이유는, 이미 걸어둔 매도 주문이
   있으면 그 수량은 다시 팔 수 없기 때문이다. 보유수량으로 잡으면 초과 주문이 되어 거부된다.
   이 규칙이 **중복 매도 방지 역할도 겸한다** — 앞선 실행이 이미 주문을 냈다면 그 수량은
   자동으로 빠지고, 전부 걸려 있으면 0주가 되어 아무 일도 하지 않는다.
3. 예약 시각보다 5분 넘게 늦게 실행됐으면(PC가 꺼져 있었던 경우) 로그에 표시한다.
   중복 방지는 2번의 주문가능수량 규칙이 담당하므로, 늦었다는 이유로 발사를 막지는 않는다.
4. **호가 추격 루프** — 끝나는 조건은 **매수 1호가가 목표가 밑으로 내려갈 때**다.
   - 매수호가창을 읽어 목표가 이상인 최우선 매수호가를 찾는다
   - 없으면 추격을 끝낸다
   - 있으면 **그 호가 가격 그대로** min(남은수량, 그 호가 물량)만큼 지정가 매도를 낸다
   - 3초 뒤 체결 여부를 확인한다
   - **최우선 호가가 그대로면 주문도 그대로 둔다.** 취소하고 같은 가격에 다시 걸면
     시간우선순위만 잃어 체결이 오히려 늦어진다
   - 최우선 호가가 **다른 가격으로 바뀌었을 때만** 취소하고 새 호가로 옮긴다
   - 추격이 끝났는데 주문이 살아 있으면 그대로 둔다(목표가 이상 가격이라 유리하다)
   - `-ChaseMinutes`(기본 60분)는 이 조건이 오지 않을 때를 위한 상한일 뿐이다
5. 추격이 끝나고 남은 수량은 **목표가에 지정가로 걸어두고** 끝낸다.

목표가는 **하한선**이다. 그보다 낮은 호가에는 절대 팔지 않는다.
주문이 거부되면 1분 뒤 재시도한다(기본 10회).

### 호가단위(틱)

목표가가 호가단위에 맞지 않으면 KIS 가 `주식주문 호가단위 오류`로 거부한다. 두 겹으로 막는다.

호가단위는 **현재가가 아니라 주문 가격**으로 정해진다. 현재가 163,100원(틱 100)인 종목도
210,200원에 주문하면 20만원 구간이라 틱이 500이다. 그래서 주문 가격의 구간을 따진다.

| 주문가 | 호가단위 |
|---|---|
| ~2,000 | 1 |
| 2,000~5,000 | 5 |
| 5,000~20,000 | 10 |
| 20,000~50,000 | 50 |
| 50,000~200,000 | 100 |
| 200,000~500,000 | 500 |
| 500,000~ | 1,000 |

**ETF/ETN 은 이 표를 따르지 않는다.** 가격과 무관하게 5원(2,000원 미만은 1원)이다.
그래서 현재가에서 잰 실제 틱이 표의 예측과 다르면 표를 버리고 실측값을 쓴다.

보정은 **내림 한 번**으로 끝낸다. 틱을 제대로 골랐으면 그걸로 유효한 가격이 되고,
입력한 목표가에서 벗어나는 폭도 한 틱 미만이다. 그래도 거부당하면 한 틱만 더 낮춰
한 번 재시도하고, 그래도 안 되면 원인을 봐야 하는 상황이라 실패로 기록한다.

## 통신이 끊기면

멈추지 않고 **10초마다 재접속**한다(`-RecoverIntervalSec`). 조회(호가·잔고·미체결·취소)는
성공할 때까지 계속 두드린다.

주문 **전송** 중에 끊긴 경우만 다르게 다룬다. 그냥 재전송하면 이중 매도가 되므로,
통신이 돌아온 뒤 **주문이 실제로 들어갔는지 먼저 확인**한다.

- 보내기 직전에 찍어둔 미체결 주문번호 목록에 없던 새 주문이 생겼다 → 접수된 것. 재전송 안 함
- 미체결에는 없는데 보유수량이 줄었다 → 그 사이 체결된 것. 재전송 안 함
- 둘 다 아니다 → 접수 안 된 것. 재전송

상한 시간까지 통신이 안 돌아오면 추격을 접는다. 이때도 **남은 수량은 목표가에 걸어둔다.**
다만 그 순간 주문 상태를 확정하지 못한 수량(전송 중 끊김·체결확인 실패·취소 실패)만은
빼놓는다. 이미 시장에 나가 있을 수 있어서 다시 걸면 이중 매도가 되기 때문이다.
그 수량은 로그에 `상태불명 N주`로 남으니 HTS 로 확인하면 된다.

## 추격이 끝나면 항상

어떻게 끝났든(목표가 미달·시간 상한·통신 장애) **남은 수량은 목표가 지정가로 걸어두고**
끝낸다. 걸어둔 주문은 그 가격에 매수가 와야 체결되고, 당일 안 팔리면 장 마감과 함께
소멸한다.

## 중복 매도 방지

주문이 거부(`rt_cd != 0`)된 경우는 주문이 생성되지 않은 것이므로 그냥 재시도한다.
문제는 **응답을 못 받은 경우** — 주문이 들어갔는지 알 수 없는데 재시도하면 이중 매도가 된다.
이때는 재시도 전에 미체결 내역과 보유수량을 조회해서, 주문이 이미 접수됐거나 체결된 흔적이 있으면
재시도하지 않고 멈춘다. 상태 확인 자체가 실패하면 역시 멈춘다 (안전한 쪽으로).

## 처음 쓸 때

반드시 `-DryRun`으로 한 번 돌려서 판단이 의도대로 나오는지 확인할 것. 실제 주문은 나가지 않는다.

```powershell
.\Invoke-ScheduledSell.ps1 -Symbol 105560 -Quantity 1 -TargetPrice 170000 -DryRun
```

## 주의

- **실전 계좌에서 실제 체결된다.** `Config.h`의 `KIS_BASE_URL`이 실전 서버로 되어 있다.
- 발사 시각에 **PC 전원이 켜져 있어야 한다** (절전은 괜찮고, 종료·최대 절전은 안 됨).
- `-WakeToRun`은 전원 옵션의 *절전 모드 해제 타이머 허용*이 켜져 있어야 동작한다.
  등록할 때 자동으로 확인해서 알려준다.
- NXT 프리마켓은 호가가 얇다. 목표가 이상 물량이 적으면 일부만 체결되고 나머지는
  목표가에 걸린 채 남는다. 일반주문은 당일 유효라 그날 안 팔리면 소멸한다.
- 키와 계좌번호는 스크립트에 들어있지 않고 실행할 때마다 `src/core/Config.h`에서 읽는다.
- 토큰 캐시(`.kis-token.json`)와 로그(`logs/`)는 `.gitignore`에 등록되어 있다. 커밋하지 말 것.

## 로그

`tools/logs/sell-YYYYMMDD.log` — 시도별 판단 근거와 KIS 응답 메시지가 남는다.
작업이 조용히 실패해도 여기를 보면 이유를 알 수 있다.
